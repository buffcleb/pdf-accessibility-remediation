# Help requests

[Guide for super admins](README.md) › Help requests

**Administration → Help requests** has every request, oldest wait first. A badge counts the ones waiting on a super
admin: new, or the person replied. Filter by status, kind or group, or search.

## Handling a request

Each request shows the conversation next to its details: the document, version, page, kind and attachments.

1. **Take it**, so others know you're on it.
2. **Reply.** The person is emailed. Add files if they help.
3. **Internal notes** are for super admins only; the person never sees them.
4. Set the status as it goes:
   - **In progress**
   - **Waiting on the person:** they get reminders after 3 and 7 days; with no reply by 10 days the request is
     closed (they can still reopen it).
5. **Open in tag viewer** goes to the version the person named, to fix it there. Saving creates a new version.

## Fixing it outside the portal

**Upload a corrected PDF** for fixes made in another tool. It must have the same pages. It becomes a **"Corrected by
support"** version and is checked like a saved edit, including the visual comparison against the version it
replaces. Failed checks are shown to you, not blocking.

## Finishing

**Finish** takes:

- **What was done:** sent to the person; required to resolve.
- **The version that fixes it.**
- **Pages to give back,** for each service the document was charged to (the usual audited usage correction).

Or **Close without changes** when nothing needs fixing.

The person sees the outcome on the document's page, with **Compare in the tag viewer**, and can **reopen** the
request within 14 days (configurable in Settings → Uploads and limits).

## Keeping a request

Requests are removed with their document's files at the end of the retention period. **Keep past retention** moves a
request to the **Saved** view so it's kept.

Group admins see their own group's requests and can reply, but not change the status.
