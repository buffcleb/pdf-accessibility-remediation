# Portal tests

Every test file of the portal suite (`portal/`): what it checks, and the to-dos (GitHub issues) and pull requests
it belongs to. How to set up and run the suites as a whole: [../README.md](../README.md).

## Running them

Every portal test needs a throwaway PostgreSQL. Start one first (each test run empties it):

```bash
docker run -d --rm --name portal-test-db -e POSTGRES_USER=portal -e POSTGRES_PASSWORD=test -e POSTGRES_DB=portal -p 55432:5432 postgres:16-alpine
```

Then, from the repository root, with the `.venv` set up:

| To run | Command |
|---|---|
| The whole suite | `.venv/bin/python -m pytest -q tests/portal` |
| One file | `.venv/bin/python -m pytest -q tests/portal/test_auth.py` |
| One test | `.venv/bin/python -m pytest -q tests/portal/test_auth.py::test_expired_code` |
| Tests whose names match words | `.venv/bin/python -m pytest -q tests/portal -k "subgroup and documents"` |
| With print output and the reason for each skip | add `-s -rs` |

The tests share the one database, so they run in one process (no `-n`). With no database they're skipped; set
`PORTAL_TEST_DATABASE_REQUIRED=1` to make that a failure. Another database: `PORTAL_TEST_DATABASE_URL` (never a
real one: the tests drop and recreate its schema).

**To-dos** are the GitHub issues the test or the PR that added it names; "(open)" marks one still open. **PRs** are
the pull request that added the file and the most recent ones that changed it; `git log --follow` on the file has
the whole history.
